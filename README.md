# TripMate: A web application for collaborative group trip planning with AI assistance

[![Quality Gate Status](https://sonarcloud.io/api/project_badges/measure?project=codeurjc-students_2026-ViajesRuben&metric=alert_status)](https://sonarcloud.io/summary/new_code?id=codeurjc-students_2026-ViajesRuben)

## Description

**TripMate** is a web application that lets a group of people plan a trip together: create the trip, build its day-by-day itinerary through activities, invite other participants, and collaborate on the plan. It includes an AI assistant able to generate itinerary proposals based on the destination, dates, budget, and preferences of the group, which the user can review and accept before adding them to the trip. Each trip can also have its own Telegram group, linked to the trip by a TripMate bot, so participants can talk about the trip in a messaging app they already use, receive their invitations there, and be notified when the plan changes. The project is initially developed as a monolithic application, designed to evolve in a second thesis project (TFG2) into a distributed services architecture.

## Version 0.1

Version 0.1 is the first working version of TripMate. A visitor can browse example itineraries on the public home page, register and log in. A registered user can edit their profile, create their own trips with a cover image, build the day-by-day itinerary of each trip with activities (with image, time, location, category and cost), follow the remaining budget and see warnings when activities overlap, fall outside the dates of the trip or exceed the budget. The administrator can search, edit, block and unblock users, and search, review and delete any trip. The application runs as a single Docker image with MySQL, published on DockerHub. These are the features B1–B8; see [Features](docs/functionalities.md) for each one with its screenshots.

## Running the application

The only requirement is [Docker](https://docs.docker.com/get-docker/) with Docker Compose 2.34.0 or later, and port 443 free. Nothing needs to be cloned: the Compose file is published on DockerHub as an OCI artifact, and it starts the application (image `rubenruiz7/tripmate`) and MySQL:

```bash
docker compose -f oci://docker.io/rubenruiz7/tripmate-compose:latest up -d --yes
```

Compose lists the variables of the file and asks for confirmation before running an application downloaded from a registry; `--yes` answers yes to that question. Remove it to review the variables first. The tag selects the version: `latest` is the last release, `0.1` (or any other release, written `MAJOR.MINOR`) a fixed one, and `dev` the last version of `main`.

Open https://localhost/ (the browser warns about the self-signed certificate) and log in as `admin@tripmate.com` with the password `admin`, or as one of the sample users, all with the password `Demo-2026`: `ana@tripmate.com`, `carlos@tripmate.com` or `laura@tripmate.com`. `SAMPLE_DATA=false` starts the application without the sample users and trips. The complete instructions (Windows, Mac and Linux, versions, sample data, stopping, and deployment on an external server) are in [Execution](docs/execution.md). To run it from the source code, see [Running and editing the code](docs/development-guide.md#running-and-editing-the-code).
